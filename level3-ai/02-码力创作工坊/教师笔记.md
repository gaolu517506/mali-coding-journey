## 3. 每课结构与卡点急救

### 第 1 课 · 写诗工坊（lesson1_写诗工坊/）

**节奏（90 分钟）**：故事一拍 3′（家园需要创造）→ 演示 5′（模糊订单 vs 精确订单同题对比）→ 跟做 40′（step1→step2→step3）→ 自主改造 25′（step4 主编工坊）→ 作品朗读互评 12′ → 钩子 5′（"诗有了，画呢？"）。

**急救表**

| 现象 | 原因 | 一句话修复 |
| --- | --- | --- |
| AI 写的诗违反约束（超字数/没按要求） | 约束太多太细，模型顾此失彼 | 保留 2~3 条最关键的，其余进"下一轮意见" |
| step4 拆货拆不开（不足三首） | AI 没守 `====` 分隔符约定 | 程序已有提醒分支；顺势讲"约定要双方一致"，重新下单 |
| 响应超时 / 限流 | 免费模型高峰排队 | 错峰、重试；教学话术："AI 也要排队" |
| 三回合改完反而更差 | 一轮意见太多，模型改丢重点 | 每回合只提一个主要意见（课程已内置此纪律） |

**话术**：订单四件套 = **角色（你是谁）/任务（做什么）/约束（守什么规矩）/示例（照这个味道）**；导演三回合 = **初稿 → 挑一个毛病 → 重拍**（一次只改一处）；人机分工 = **AI 供货，人当主编**（挑与改是你的工作）。

### 第 2 课 · 画画工坊（lesson2_画画工坊/）

**节奏**：词汇表课 15′（step1 零依赖 + 体检员游戏）→ 跟做 40′（step2→step3）→ 画廊布展 20′（step4）→ 互评 10′ → 钩子 5′（"AI 会画了——那让它给咱们的游戏供货呢？"）。

**急救表**

| 现象 | 原因 | 一句话修复 |
| --- | --- | --- |
| .svg 双击打不开 / 显示为文本 | 关联到编辑器了 | 拖进浏览器窗口，或浏览器"打开文件" |
| AI 返回里剥不出 `<svg`（脚本报错/空文件） | AI 没按格式交货 | 重跑一次；这是既定教学点（L3 会系统解决） |
| 画出的东西超纲（渐变/阴影） | 订单约束被 AI 忽略 | 正好演示"验收"：发现超纲 = 退回重画 |
| 三幅画风不统一 | AI 每次生成都是"重新想" | 正常现象；要统一就给更死的坐标级约束 |

**话术**：闭集 = **词汇表外的词不许出现**（真实案例：本课程码力形象的 AI 概念图，就是靠"禁渐变/阴影/高光"让 AI 的产出能落进 Scratch 矢量编辑器）；SVG = **画出来的代码、写出来的画**——turtle、pygame、SVG、HTML 一脉相承；导演位 = **不碰代码，只提意见**。

**关于文生图的说明**：本站学生主线用 SVG（代码画）而非文生图 API——理由：① 各家文生图接口不统一且异步轮询复杂；② SVG 与"作品即代码"的体系世界观一致；③ 生成的画可以直接进游戏/网页被程序使用。智谱 CogView（文生图）可作为**教师投屏彩蛋**：`POST /images/generations`，body `{"model":"cogview-3-flash","prompt":"..."}`，返回 url，课堂打开即看——两段代码，演示足够。

### 第 3 课 · 关卡工厂（lesson3_关卡工厂/）

**节奏**：读图纸 15′（step1 零依赖，含"坏图纸体检"）→ 跟做 40′（step2 下单 → step3 验证员）→ 毕业作品 25′（step4 上货三步曲）→ 通关互拍 10′ → 结课仪式 5′（读毕业检查单，念"回家吧"）。

**急救表**

| 现象 | 原因 | 一句话修复 |
| --- | --- | --- |
| AI 设计的关卡行宽不等于要求值 | 模型"数字符"能力有限，主题构图时按需要来 | 课程验证员已改为自适应口径（行等长即可，列数游戏自适应）——**不要跟 AI 的数数能力较劲，约束要落在真正重要的地方** |
| 交稿裹着 ```代码块 / 变量赋值 / 解释文字 | AI 包装习惯五花八门（实测四种形态） | 课程剥壳函数已层层处理（代码块→三引号→空格压缩→纯地图行兜底） |
| 重试 2 次仍不合格 | 模型波动 | 代码有兜底分支；多跑一次，或现场带学生人工修一张（人工兜底也是教学） |
| 生成关卡太简单/太密 | 提示词没给数值导向 | 在订单里加"硬垃圾比例""垃圾总数不低于 N"等数值要求 |

**话术**：验证员 = **AI 想，程序查**（谁都不能偷懒）；退回重修 = **把体检报告原样发回去**（AI 看得懂自己的错误）；约束设计 = **落在一致性上，不落在数数上**（行等长 AI 做得到，"恰好 14 个字符"做不到）——这是本课最深的一课：**写约束前先了解执行者的能力边界**。

**本课开发期实测记录（教研素材，课堂可当案例讲）**：glm-4-flash 交稿见过四种包装（裸文本 / 三引号 / ```python 代码块 / `output = """` 赋值），见过空格对齐图案，见过把 14 字符画成 19——全部被剥壳 + 自适应验证员接住。结论一句话：**AI 的产出不可信任但可用，前提是你有验证器。**

## 4. 分层任务（全站）

- 基础：L1 step1–2（订单对比 + 模板）、L2 step1–2（词汇表 + 第一幅画）、L3 step1（读图纸）
- 进阶：L1 step3–4（导演三回合 + 主编工坊）、L2 step3–4（改画 + 画廊）、L3 step2–3（AI 图纸 + 验证员）
- 挑战：主题诗集 / 角色设计 / 关卡策划师三单
- 毕业验收：AI 生成关卡 → 通过验证员 → 粘进第二站真实开打一局 → 在毕业检查单四个"□"全部打勾

## 5. 衔接钩子与体系闭环

- 承上：上一站"艾芯会说话了" → 本站"艾芯会创造"（说话→创造的进阶由故事驱动：家园重建需要创造）
- 闭环三件套（结课仪式逐条点）：第一站的"闭集词汇表"方法论 → 本站画画的订单纪律；第二站的字符地图 → 本站 AI 供货的格式；第二站的游戏 → 本站关卡的验收场
- 收官叙事：码力向太空发出信号"回家吧"——五个项目、三级进阶、一个互相咬合的小世界
- 课程外延：把《码力回家》整体讲给家长/面试官听，本身就是最高级的"提示词工程"练习

## 6. 与试讲的接口

- **主文档面试叙事指定的 AI 试讲素材**："现场让 AI 当堂写诗"——直接用 L1 step2 订单模板（四件套现写、现跑、现读），哇点自然；备选 L3"AI 设计关卡 → 验证员体检 → 退回重修"的闭环演示（哇点 = 机器抓到 AI 的错）
- 磨法五维度照旧；AI 课专属加分：演示中途"故意"让 AI 出一次错再当场修复——比一帆风顺更能体现工程素养

## 7. 教学设计决策（为什么这样切）

- **写诗先行**：文字生成最直观、门槛最低，订单四件套在文字上练熟，画和关卡只是"换货物不换方法"
- **画画用 SVG 而非文生图**：见第 2 课说明——接口统一性、体系世界观、产出可被程序使用三个理由；文生图降级为教师彩蛋
- **关卡工厂做毕业课**：它是全体系唯一"AI 产出直接进另一个项目"的课——闭环落地的仪式感 + 验证员这一真实工程角色，都只有它承载得动
- **验证员口径自适应而非硬数字**：开发期实测 glm-4-flash 数不准字符数（14 要求交 19），验证改为"行等长 + 字符集 + 行数区间"，列数交由第二站 `build_from_map` 自适应——这本身成为"约束要落在执行者能力边界内"的教学素材
- **ask() 的封装节奏**：与前两站同一能力主线（Scratch 重复执行 → for → def → API 封装 → 验证函数），学生到本站已把"重复之痛 → 抽象"内化
